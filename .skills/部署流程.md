# RSSHub 推荐部署流程

> 适用于云服务器 ECS（Ubuntu 22.04+）从 0 到 1 部署 RSSHub
> 最后修订: 2026-08-13

---

## 1. 架构概述

四容器架构，零入站端口设计：

| 服务 | 镜像 | 容器端口 | 宿主机绑定 | 对外暴露 |
|------|------|---------|-----------|---------|
| rsshub | `diygod/rsshub`（预构建） | 1200 | `127.0.0.1:1200` | 仅本地回环 |
| browserless | `browserless/chrome` | 3000 | — | Docker 内网 |
| redis | `redis:alpine` | 6379 | — | Docker 内网 |
| cloudflared | `cloudflare/cloudflared:latest` | — | — | 出站隧道，不监听端口 |

**远程访问原理**：用户浏览器 → Cloudflare 边缘（HTTPS 443）→ 出站隧道 → cloudflared 容器 → rsshub:1200（Docker 内网）。服务器**无需开放任何入站端口**，安全组只需保留 22（SSH）。

**预构建镜像设计**：使用 Docker Hub / GHCR 上的官方预构建镜像 `diygod/rsshub`，支持 amd64 和 arm64 双平台。无需上传源码、无需本地编译，`docker compose up -d` 秒级启动。browserless 提供远程 Chromium 渲染能力，供需要 Puppeteer 的路由使用。

**本地开发模式**：`docker compose up -d`（不加 `--profile tunnel`），只起 rsshub + browserless + redis，访问 `http://localhost:1200`。

## 2. 前置准备

### 2.1 ECS 实例要求

| 项 | 推荐值 | 说明 |
|----|--------|------|
| 操作系统 | Ubuntu 22.04 LTS | 长期支持版 |
| CPU | 1 核 | RSSHub 轻量够用 |
| 内存 | 2 GB | Node.js + Redis + browserless |
| 系统盘 | 20 GB SSD | OS + Docker + 镜像 |
| 公网带宽 | 按量付费 5 Mbps | 起步够用 |

安全组入方向规则（云控制台配置）：

| 协议 | 端口 | 来源 | 用途 |
|------|------|------|------|
| TCP | 22 | 你的 IP/32 | SSH 管理 |

> Cloudflare Tunnel 是出站连接，无需开放 80/443/1200/6379。出站方向需能访问 Cloudflare 隧道端口（TCP 7844/443），云服务器默认放行全部出站，一般无需额外配置。

### 2.2 SSH 连接

```bash
ssh root@YOUR_ECS_IP
```

## 3. 部署步骤

### 3.1 安装 Docker

```bash
# 一键安装 Docker
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker

# 加入 docker 组免 sudo
sudo usermod -aG docker $USER
exit

# 重新登录让组权限生效，验证安装
ssh root@YOUR_ECS_IP
docker --version && docker compose version
```

国内 ECS 拉取镜像慢时配置加速器：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com"
  ]
}
EOF
sudo systemctl restart docker
```

### 3.2 上传配置文件

**本地执行**（替换 `YOUR_ECS_IP` 和项目路径）：

```bash
cd /path/to/RSSHub

# 打包配置文件（COPYFILE_DISABLE 防止 macOS 元数据污染）
COPYFILE_DISABLE=1 tar -czf rsshub-deploy.tar.gz \
    docker-compose.yml \
    .env.example

# 验证 tar 包内无 macOS 元数据文件（应无输出）
tar -tzf rsshub-deploy.tar.gz | grep '\._'

# 上传到 ECS
scp rsshub-deploy.tar.gz root@YOUR_ECS_IP:/opt/
```

**ECS 上执行**：

```bash
cd /opt
mkdir -p rsshub && tar -xzf rsshub-deploy.tar.gz -C rsshub
cd rsshub

# 清理可能残留的 macOS 元数据文件（兜底）
find . -name "._*" -type f -delete
```

> `docker-compose.yml` 已集成 Cloudflare Tunnel 和 browserless，关键设计：
> - rsshub 端口绑定 `127.0.0.1:1200`，公网无法直达，仅 cloudflared 通过 Docker 内网访问
> - browserless 不暴露端口，仅 rsshub 通过 WebSocket `ws://browserless:3000` 访问
> - redis 不暴露端口，仅 rsshub 通过 `redis://redis:6379` 访问
> - cloudflared 使用 `profiles: ["tunnel"]`，本地开发时不启动
> - `depends_on` 使用 `condition: service_healthy`，rsshub 等 redis/browserless 健康后才启动，cloudflared 等 rsshub 健康后才启动
> - 四个服务同在 `rsshub-net` Docker 网络，通过 Docker DNS 互相解析

### 3.3 配置环境变量

```bash
cd /opt/rsshub

# 从模板创建 .env
cp .env.example .env
chmod 600 .env

# 填入 Cloudflare Tunnel Token（见 3.4 节获取）
nano .env
```

**可选环境变量**（按需在 `.env` 中添加）：

| 字段 | 说明 |
|------|------|
| `CLOUDFLARE_TUNNEL_TOKEN` | Cloudflare 隧道 Token（见 3.4 节） |
| `ACCESS_KEY` | RSSHub 访问控制密钥，设置后需通过 `key` 参数访问 |
| `ALLOWLIST` | 白名单路由，逗号分隔 |
| `PROXY_URI` | 代理地址，国内 ECS 访问部分源站需要 |

> 完整环境变量列表参见 [RSSHub 文档](https://docs.rsshub.app/deploy/config)。

### 3.4 配置 Cloudflare Tunnel

rsshub 绑定 `127.0.0.1:1200`，公网无法直达。通过 Cloudflare Tunnel 暴露为 HTTPS 域名 — 免费、零入站端口、自动证书，替代传统 Nginx + Certbot 方案。

> Tunnel 属于 Cloudflare Zero Trust 免费档，50 用户内零成本，不限连接数、不限流量。个人 RSSHub 使用永久免费。

**步骤 1：创建隧道并获取 Token**

1. 登录 [Cloudflare Zero Trust](https://one.dash.cloudflare.com/) 控制台
2. Networks → Tunnels → Create a tunnel → 选 `Cloudflared` 类型
3. 命名隧道，创建后复制 **Tunnel Token**（形如 `eyJh...` 的长字符串）
4. 将 Token 填入 `.env`：`CLOUDFLARE_TUNNEL_TOKEN=eyJh...`

**步骤 2：配置 Public Hostname（回源路由）**

在隧道的 Public Hostname 页加一条：

| 字段 | 值 |
|------|------|
| Subdomain | `rss`（或任意子域名） |
| Domain | `你的域名.com`（须托管在 Cloudflare DNS） |
| Type | `HTTP` |
| URL | `rsshub:1200`（Docker 内网域名，**不是 localhost**） |

> cloudflared 与 rsshub 同在 `rsshub-net` Docker 网络，通过 Docker DNS 解析 `rsshub`。Cloudflare 边缘自动提供 443 HTTPS + 橙云代理 + DDoS 防护，DNS 的 CNAME 记录由隧道自动生成，无需手动配置。

**步骤 3：启动并验证隧道**

```bash
cd /opt/rsshub
docker compose --profile tunnel up -d
docker compose logs cloudflared | grep "Registered tunnel connection"
# 看到 4 条 "Registered tunnel connection" 即隧道建立成功
```

访问 `https://rss.你的域名.com/` 即可。

### 3.5 验证部署

```bash
# 1. 本地健康检查（应返回 ok）
curl http://127.0.0.1:1200/healthz

# 2. 公网访问（需先完成 3.4 隧道配置）
# https://rss.你的域名.com/

# 3. 测试 RSS 路由
# https://rss.你的域名.com/github/blog/DIYgod
```

## 4. 常用运维命令

```bash
cd /opt/rsshub

# ---- 生命周期 ----
docker compose --profile tunnel up -d        # 启动含隧道
docker compose --profile tunnel down          # 停止含隧道
docker compose up -d                          # 本地开发模式（无隧道）

# ---- 状态与日志 ----
docker compose ps
docker compose logs -f rsshub --tail 100
docker compose logs -f cloudflared            # 隧道连接日志
docker compose restart cloudflared            # 重启隧道客户端

# ---- 升级 ----
docker compose pull                           # 拉取最新镜像
docker compose --profile tunnel up -d         # 重新创建容器

# ---- 清理 ----
docker compose --profile tunnel down          # 停止所有服务
docker compose --profile tunnel down -v        # 停止并删除数据卷（丢缓存）
```

> 使用 `--profile tunnel` 时，`down` 也会停止 cloudflared。本地开发不带该参数即可。

## 5. 故障排查

### 5.1 容器启动失败

```bash
docker compose logs rsshub
docker compose logs browserless
docker compose logs redis
```

常见错误：
- rsshub 无法连接 redis → 检查 redis 容器是否健康：`docker compose ps redis`
- rsshub 无法连接 browserless → 检查 browserless 容器是否健康：`docker compose ps browserless`
- browserless 崩溃 → 内存不足，检查 `dmesg | grep -i oom`

### 5.2 cloudflared 隧道连不上 / 域名无法访问

```bash
docker compose logs cloudflared
```

常见错误：
- `error validating token` → `CLOUDFLARE_TUNNEL_TOKEN` 未填或填错
- 长时间无 `Registered tunnel connection` → ECS 出站被限，确认能出站到 TCP 7844/443
- 域名访问返回 502 → Public Hostname 的 URL 应填 `rsshub:1200`（Docker 内网），不是 localhost
- 域名访问返回 1033 → 隧道未连接，检查 cloudflared 是否在运行
- 容器列表没有 cloudflared → 启动时漏了 `--profile tunnel` 参数

### 5.3 本地能访问、公网不能访问

```bash
# 1. 本地健康检查（应返回 ok）
curl http://127.0.0.1:1200/healthz

# 2. cloudflared 是否运行
docker compose ps cloudflared

# 3. 隧道是否注册成功
docker compose logs cloudflared | grep "Registered tunnel connection"

# 4. Cloudflare 控制台 Public Hostname 是否指向 rsshub:1200
```

### 5.4 RSS 路由返回错误

- 路由返回 403/429 → 源站反爬，可能需要配置 `ACCESS_KEY` 或 User-Agent
- 路由返回超时 → 部分路由需要 Puppeteer 渲染，检查 browserless 是否正常运行
- 路由返回空 → 源站页面结构变更，检查路由是否需要更新

### 5.5 browserless 内存不足（OOM）

```bash
free -h
# browserless Chromium 渲染占用 300-500 MB
# 2G 内存 ECS 建议关闭不需要的路由，或升级到 4G
```

## 6. 安全清单

部署前逐项确认：

- [ ] rsshub 端口绑定 `127.0.0.1:1200`（已由 docker-compose.yml 保证）
- [ ] browserless 不暴露端口（已由 docker-compose.yml 保证）
- [ ] redis 不暴露端口（已由 docker-compose.yml 保证）
- [ ] 安全组仅开放 22 端口（未开放 80/443/1200/6379）
- [ ] `.env` 文件权限 `chmod 600`
- [ ] `CLOUDFLARE_TUNNEL_TOKEN` 已配置且隧道连接正常
- [ ] SSH 已禁用密码登录（仅用密钥）
- [ ] 如需访问控制，已配置 `ACCESS_KEY`

## 附录：一键部署脚本（可选）

> 以下脚本自动完成 Docker 安装、配置文件上传检查、拉取镜像并启动。**需先完成 3.2 上传配置文件到 `/opt/rsshub`**。

保存为 `deploy.sh`，在 ECS 上执行：

```bash
#!/bin/bash
set -e

DEPLOY_DIR="/opt/rsshub"

echo "===== RSSHub 一键部署脚本 ====="

# 1. 检查并安装 Docker
if ! command -v docker &> /dev/null; then
    echo "安装 Docker..."
    curl -fsSL https://get.docker.com | sh
    systemctl enable --now docker
fi

# 2. 检查配置文件
cd $DEPLOY_DIR
if [ ! -f docker-compose.yml ]; then
    echo "❌ docker-compose.yml 不存在，请先执行 3.2 节上传配置文件"
    exit 1
fi

if [ ! -f .env ]; then
    cp .env.example .env
    chmod 600 .env
    echo "⚠️  请编辑 $DEPLOY_DIR/.env 配置隧道 Token 后再运行："
    echo "   nano $DEPLOY_DIR/.env"
    echo "   隧道：CLOUDFLARE_TUNNEL_TOKEN（见 3.4 节）"
    exit 1
fi

# 3. 拉取镜像并启动（含 Cloudflare Tunnel）
echo "拉取镜像并启动..."
docker compose --profile tunnel up -d

# 4. 健康检查（本地回环）
echo "等待 RSSHub 启动..."
sleep 10
if curl -s http://127.0.0.1:1200/healthz | grep -q "ok"; then
    echo "✅ 部署成功！"
    echo "   本地健康检查：http://127.0.0.1:1200/healthz"
    echo "   公网访问：请完成 Cloudflare Tunnel 配置后访问 https://你的域名/"
    echo "   隧道日志：docker compose logs cloudflared"
else
    echo "❌ 健康检查失败，查看日志："
    echo "   docker compose logs rsshub"
fi
```

使用方法：

```bash
chmod +x deploy.sh
./deploy.sh
```
